Project: KingAI – 생성형 AI 캐릭터 채팅 플랫폼

1. 개요

KingAI는 사용자가 직접 만든 캐릭터와 지속적인 세계관 기반 대화를 할 수 있는 웹 기반 AI 채팅 플랫폼입니다. 단순 질문·답변 챗봇이 아니라, 캐릭터 설정, 이미지, 태그, 장기기억을 모두 활용해 마치 비주얼 노벨처럼 캐릭터와 상호작용할 수 있도록 설계했습니다.

  • 사용자가 캐릭터를 생성하고, 상세 설정(프로필/세계관/규칙)을 작성
  • 캐릭터별로 여러 장의 이미지를 업로드하고 {img:N} 토큰으로 활용
  • 각 캐릭터마다 독립된 대화방과 대화 히스토리, 롱텀 메모리(LTM)를 유지
  • Gemini 2.5 Pro와 연동해 3인칭 소설체 RP 스타일로 응답 생성

2. 기술 스택

Frontend

  • React + TypeScript + Vite
  • React Router 기반 SPA 화면 구성
  • Tailwind + 커스텀 CSS로 다크모드 채팅 UI
  • 슬라이더로 사고 토큰 / 출력 토큰 / n턴 제어

Backend & Infra

  • Spring Boot 3, Spring Security
  • JPA / Hibernate + MySQL (User, Work, Image, Conversation, Message, ChatUsage, ModelPricing 등)
  • Gemini 2.5 Pro (Vertex AI) REST 연동
  • 대화별 토큰/비용 로깅 및 과금 계산 로직

3. 구현된 기술

① 캐릭터 생성 & 이미지 슬롯 시스템

  • /api/characters API로 캐릭터 생성 (제목, 상세 설정, 공개 여부, 태그)
  • /api/characters/{id}/images 엔드포인트로 이미지 업로드 (slotIndex, label)
  • 프론트에서는 {img:0}, {img:1} 같은 토큰을 채팅에 섞어 쓰면 자동으로 해당 슬롯 이미지를 렌더링

② 캐릭터별 대화방 & 장기기억 구조

  • Conversation 엔티티로 캐릭터별 대화 세션 관리 (user, work, memoryTurns, rollingSummary)
  • Message 엔티티로 모든 user / model 메시지 순서대로 저장
  • 프론트에서 선택한 n턴 값에 따라 최근 n턴만 LLM에 넘기고, n턴마다 전체 대화를 요약해 rollingSummary에 저장하는 LTM 구현

③ Gemini 2.5 Pro 연동 & 프롬프트 엔지니어링

  • Vertex AI generateContent REST API를 직접 호출하는 VertexGenerateContentCaller 설계
  • System Prompt에서 {"reasoning": "...", "final": "..."} 구조의 JSON만 반환하도록 강제
  • 3인칭 소설체 RP 규칙, 캐릭터 스펙, 이미지 토큰 사용 규칙 등을 System Prompt에 정리
  • LLM이 JSON을 깨뜨려도 ObjectMapper + regex로 최대한 final을 복구하는 방어 로직 구현

④ 토큰 / 비용 계산 및 모니터링

  • Gemini 응답의 usageMetadata에서 promptTokenCount, candidatesTokenCount, thoughtsTokenCount 분리
  • 입력 / 출력 / 사고 토큰을 따로 저장하고, ModelPricing 테이블 기반으로 1k 토큰당 단가를 곱해 원화 비용 계산
  • ChatUsage 엔티티로 대화별 토큰 사용량과 비용을 로그로 남김
  • 프론트에서는 마지막 응답 기준으로 “모델명 / 토큰 수 / 추정 비용(원)”을 실시간으로 표기

⑤ 프론트엔드 대화 UI & 슬라이더 제어

  • CharacterChatPage에서 캐릭터 정보 + 이미지 + 대화 + 장기기억 UI를 한 화면에 구성
  • 오른쪽 사이드바에서 사고 토큰(128~4096), 출력 토큰(512~8192), n턴을 슬라이더로 직관적으로 제어
  • 각 캐릭터별 대화 상태(메시지, conversationId, LTM)를 localStorage에 저장해 새로고침에도 유지

결과

✔ 캐릭터 생성 → 이미지 업로드 → 캐릭터별 AI 채팅까지 한 흐름으로 동작하는 프로토타입 완성

✔ n턴 LTM 요약 구조 덕분에, 긴 대화도 맥락을 유지하면서 토큰 사용량을 통제 가능

✔ 프론트에서 사고 토큰 / 출력 토큰 / n턴을 조절하며, 비용과 품질을 직관적으로 실험할 수 있는 환경 구축

회고

① 데이터 모델링, ② 히스토리 관리, ③ 비용 구조, ④ UI 제어까지 모두 설계해야 한다는 점을 체감했습니다.

• 다음 단계로는 TTS, 이미지 생성까지 붙여서 “대화 + 보이스 + 비주얼”이 통합된 캐릭터 시뮬레이션 플랫폼으로 확장할 계획입니다.
