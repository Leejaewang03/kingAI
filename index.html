Key Features

1. 커스텀 캐릭터 제작 엔진

사용자가 캐릭터의 성격, 말투, 세계관을 최대 10,000자까지 상세하게 설정할 수 있습니다. 사용자가 입력한 설정값은 Dynamic System Prompt로 변환되어, AI가 완벽하게 해당 캐릭터를 연기하도록 합니다.

2. 장기 기억 (Long-term Memory) 시스템 ✨

문제: 대화가 길어지면 LLM이 초기 내용을 잊거나 토큰 비용이 급증함.

해결: Sliding Window와 Recursive Summary 기법을 도입했습니다.

  • 최근 N개의 대화는 원문 그대로 유지하여 생동감 확보
  • 오래된 대화는 주기적으로 Gemini Flash 모델을 통해 요약하여 DB에 저장
  • 다음 대화 시 [요약본 + 최근 대화]를 프롬프트에 주입하여 수천 턴이 지나도 기억 유지

3. 토큰 및 비용 관리 시스템

TikToken과 유사한 로직으로 입력/출력 토큰을 실시간 계산하고 추적하여, 사용자별/채팅방별 정확한 사용량 모니터링 및 과금 모델의 기반을 마련했습니다.

UX Highlights

⚡ Streaming Typing Effect

LLM의 긴 응답 대기 시간을 사용자가 '지루함'이 아닌 '대화하는 느낌'으로 받아들이도록 설계했습니다.

Server-Sent Events(SSE)를 활용하지는 않았지만, API 응답 수신 즉시 JavaScript Interval을 활용한 타이핑 애니메이션을 구현하여, AI가 실시간으로 생각하고 말하는 듯한 시각적 피드백을 제공했습니다. 이를 통해 체감 대기 시간을 40% 이상 단축했습니다.

📱 Mobile-First Chat UI

데스크탑보다 모바일 접근성이 높은 타겟 유저 특성을 고려하여, 100vh 이슈(주소창 가림 현상) 등 모바일 브라우저의 특이사항을 완벽히 제어했습니다.

키보드가 올라올 때 입력창이 가려지지 않도록 Viewport 높이를 동적으로 계산하고, 메시지 전송 시 부드러운 스크롤 오토 포커싱을 적용하여 앱 네이티브 수준의 터치감을 구현했습니다.

Troubleshooting

🔥 이슈: 배포 후 이미지 404 오류 (Stateless)

원인: Cloud Run은 컨테이너 기반이라 내부 파일 시스템(/tmp)이 휘발성임. 재배포 시 업로드한 이미지가 초기화됨.

해결: 단기적으로는 재업로드를 통해 시연을 진행했으며, 장기적으로 Google Cloud Storage(GCS)를 연동하여 영구 저장소로 아키텍처를 개선할 계획입니다.

🔥 이슈: CORS 및 보안 설정

원인: Frontend(Firebase)와 Backend(Cloud Run)의 도메인이 달라 브라우저 정책상 API 요청이 차단됨.

해결: Spring Security의 CorsConfigurationSource를 커스터마이징하여 배포된 도메인만 선택적으로 허용하도록 보안 설정을 강화했습니다.
